## 二、需求解读

MyToken 是一个**个人额度聚合查询工具**：把用户分散在各 API 供应商平台的余额/额度/订阅用量汇总到一个竖版瀑布式页面，一键查看各平台还剩多少可用额度。

核心交互：
- 每供应商 = 一个**纵向排列的模块**（QinyAPI→DeepSeek→OpenCode-Go→硅基流动→各家 Coding Plan→后续扩展）。
- 部分供应商标题带**可新开页面的 URL**（QinyAPI、OpenCode-Go、硅基流动）。
- 每个模块仅两个用户操作：**鉴权密钥填入栏** + **启用开关**。
- 密钥隐身显示，后带 **? 浮窗**弹出该供应商鉴权密钥获取说明 md 文档。
- 开关开启时**即时鉴权**：鉴权不成功开关无法开启；开关不开启模块默认收起（减少渲染压力）。
- 左上角 = icon + 「MyToken」（点击跳转仓库）；右上角 = 图标功能区（主题：浅色/暗色/跟随系统，默认跟随系统，后续功能从右向左增加）。

## 三、关键发现（来自调研，决定架构）

### 3.1 「纯前端直连」在多数供应商上是不可行的（CORS 是硬约束）

调研核心结论：**各供应商的余额/额度接口大多未对浏览器跨域开放**。参考插件（一款 dsh web 费用统计插件，其展示方式为本项目设计参考）正是为此采用「宿主后端代理 RPC」架构——浏览器不直接跨域调用官方接口，而是由后端代发请求，一举解决 **CORS**、**特殊 UA** 与 **API Key 回落浏览器** 三件事。

| 供应商 | 问题 | 是否需代理 |
|--------|------|-----------|
| QinyAPI(new-api) | 用户级接口 CORS 未保证，且需「令牌+用户id」双头 | 建议代理 |
| DeepSeek 官方 | 余额接口 `/user/balance` CORS 未保证 | 建议代理 |
| OpenCode-Go | 前置 **Cloudflare**，必须浏览器 UA 否则 error 1010 | **必须代理**（控制 UA） |
| 硅基流动 | `/v1/user/info` CORS 未保证 | 建议代理 |
| 各家 Coding Plan | 各端点 CORS 未保证 | 建议代理 |

> **决策**：采用「前端 SPA + 轻量后端代理层」。这使前端体验仍是纯前端 SPA，但查询请求经同源代理转发，规避 CORS、注入必要 UA、保护 Key。**Key 仍由用户在页面输入、仅存前端 localStorage**（个人工具可接受），代理只做转发、不持久化 Key、不打日志。

### 3.2 各供应商「能查什么」的边界（决定每个模块展示内容）

| 供应商 | 能查的 | 不能查的 |
|--------|--------|---------|
| **QinyAPI** | 余额 `/api/user/self`（quota/500000→美元）；花费 `/api/log/self?type=2`（今日/累计） | — |
| **DeepSeek 官方** | 仅余额 `/user/balance`（`balance_infos[]`，多币种按 CNY 优先+正余额挑选） | 今日消耗 / token 用量 / 按模型费用 / 周期费用（**无官方统计 API**；参考插件靠拦截 llm 流本地记账，MyToken 是查询工具、不做代理，故无法提供） |
| **OpenCode-Go** | 订阅用量 `/zen/go/v1/usage` → `usage.rolling/weekly/monthly` 各 `{percent已用%, resetsAt}` | — |
| **硅基流动** | 余额 `/v1/user/info` → `data.activeBalance/totalBalance`（元，直接展示） | 花费明细（**无公开 API**） |
| **Coding Plan** | 各家窗口/余额（Anthropic 5h/7d、Z.ai v3、MiniMax 剩%、Kimi 余额、OpenRouter credits） | SCNet 无 API 端点（V1 不纳入） |

> 影响：**DeepSeek 模块只展示余额**（今日/token/费用等统计无法实现，V1 明确不含）；**硅基流动只展示余额**；其余模块按各自能力展示。这是对用户原始设想的一个重要澄清，需在 SSOT 中明示。

### 3.3 美术与 md 渲染参考（NyaaChat）

- **美术基调**：Tailwind v4；暗色基 `#0A0A0A`/`#111111` + 白色半透毛玻璃浮层(`backdrop-blur-xl`)；蓝 primary(`blue-500/600`) + 紫 secondary（天然适合区分模块）；红/琥珀/绿状态色；蓝紫渐变 Logo(`from-blue-600 to-indigo-500`)；柔和辉光背景；蓝色图形滚动条；圆角 `rounded-xl/2xl`;阴影 `elevation-1/2/3`+`shadow-glow`；字体 Inter / Space Grotesk / JetBrains Mono；深浅双主题经 `.dark` class 切换。
- **md 渲染**：`react-markdown` + `prose`（`@tailwindcss/typography`）。鉴权说明浮窗 = 复用通用 Modal 壳 + `fetch(public/*.md)` 懒加载 + 链接 `target="_blank"`。

## 四、架构设计

### 4.1 层级

```
浏览器 (React SPA)
   │  /api/* 同源调用（fetch）
   ▼
Node/Express 代理层（极简，仅转发 + 处理头 + 错误归一）
   │  注入必要 UA / 转发 Bearer / 不透传 Key 日志
   ▼
各供应商官方接口（QinyAPI / DeepSeek / OpenAI-Go / 硅基 / Coding Plan 各家）
```

### 4.2 供应商适配器抽象（前端核心设计）

统一 `Provider` 接口，每供应商一个适配器：

```
interface ProviderDef {
  id: string;                 // "qinyapi" | "deepseek" | ...
  name: string;               // 展示名
  titleUrl?: string;          // 标题可跳转 url（QinyAPI/OpenCode-Go/硅基）
  kind: "balance" | "quota" | "usage-window" | "both";
  fields: AuthField[];        // 密钥输入字段（key 隐藏显示；QinyAPI 需"令牌+用户id"）
  docPath: string;            // 鉴权说明 md（public/docs/<id>.md）
  // 查询实现（经代理）
  query(creds, signal): Promise<ProviderResult>;
  enabled: boolean;           // 启用开关（localStorage）
}
```

状态管理：**无 Redux/Zustand**，顶层 `useState` + 自定义 hooks（`useProviders`/`useBalances`）+ props 下传，`localStorage` 持久化密钥与开关。

### 4.3 代理层职责

- 路由 `/api/providers/:id/query`，按 `id` 分派到对应上游。
- 注入必要自定义头（QinyAPI 的 `New-Api-User`）、控制 UA（OpenCode-Go 浏览器 UA）、转发 `Authorization: Bearer`。
- 基于硬编码域名白名单，**Key 只发往各家官方域名**。
- 错误归一（401/403/404/5xx → 前端中文提示）。
- **绝不把 Key 写日志**。

## 七、风险识别与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 各家接口不稳定/变更（如 Z.ai v4→404 需 v3） | 中 | 各家适配器独立 + 端点可配 + 错误归一 404 提示「端点变更」 |
| CORS / Cloudflare 拦截 | 已解 | 后端代理统一处理 |
| API Key 存 localStorage 有 XSS 暴露面 | 中 | 纯本地个人工具可接受；不做任何分享/上报；提示用户；代理不落日志 |
| DeepSeek 无法提供 token/费用统计 | 明示 | V1 模块仅显示余额，SSOT 明确边界 |
| SCNet 无 API | 明示 | V1 不纳入 |
| 多币种（DeepSeek USD/CNY）数值口径 | 中 | 复用「CNY 优先+正余额」挑选逻辑 |
| OpenCode-Go 需浏览器 UA | 已解 | 代理注入 UA |
| 第三方 md 内链接 | 低 | `target="_blank" rel="noopener"` |
