## 二、安全性

### ✅ 2.1 域名白名单真正生效

`server/src/providers.ts` 所有 `Endpoint.url` 均**硬编码**，且 `server/src/index.ts` 在分派后强制校验
`provider.hosts.includes(url.host)`（第 164 行），未命中直接 403 `拒绝请求非白名单域名`。

- `forwardQuery` 场景（QinyAPI `op=log`）会用 `url.origin + url.pathname + buildForwardQuery(...)` 重组 URL，
  但 origin/pathname 均来自已被白名单校验的 `rawUrl`，重组后仍停留在白名单 host，**不会因此逃逸到任意域**。
- ✅ 结论：**密钥只可能发往白名单内的官方域名，不存在透传任意域的路径。**

### ✅ 2.2 密钥不落日志

- 日志仅打印 `[proxy] <id> -> <host><pathname> <status>`（index.ts 第 174/178/186 行），
  不打印 Authorization 头、不打印完整 URL、不打印查询参数。
- `fetchUpstream` 携带 `headers`（含 Authorization）但不会写入任何日志。
- `RESERVED_QUERY`（第 30 行）在透传 query 时剔除 `apiKey/key/token/op/userId/New-Api-User/Authorization`，
  防止密钥以查询参数形态被透传。
- ✅ 结论：密钥不落代理日志；前端亦无任何密钥上报/分享逻辑。

### ⚠️ 2.3 【中】代理监听所有网卡 + CORS 反射任意 Origin

- `app.listen(PORT)`（index.ts 第 219 行）未指定 host，Express 默认绑定 `0.0.0.0`（全网卡）；
- CORS 中间件把请求方 `Origin` 原样反射进 `Access-Control-Allow-Origin`（第 198 行），
  即**允许任意跨域来源**调用该无鉴权代理。

**影响评估**：代理是无状态转发，密钥由前端每请求显式携带，且后端只放行白名单域名——
恶意页面无法读取受害者 localStorage 中的密钥，也无法让受害者浏览器替它带密钥，因此**不构成密钥窃取通道**。
但 LAN 上任意网页/进程均可把你本机当免费中继去打白名单域名（虽无密钥基本无返回价值）。

**建议**：
- 开发绑定回环：`app.listen(PORT, "127.0.0.1")`（生产本就由 nginx 同源反代，可加）。
- 或把 `Access-Control-Allow-Origin` 收敛为固定白名单（如仅本地 Vite dev 源），不要反射任意 Origin。
- 优先级：低～中，个人工具可接受，但属低成本加固。

### ℹ️ 2.4 【低】密钥明文存 localStorage

- `mytoken-provider-values` 以明文 JSON 存 localStorage（useProvidersConfig.ts）。
- 这是 **D6 决策**（个人工具可接受），且当前代码**无 XSS 暴露面**：react-markdown 默认转义、
  无 `dangerouslySetInnerHTML`、md 均来自静态 `public/docs/*.md`（非用户输入）。
- 建议：文档/UI 已提醒「勿外泄」，保持现状即可；未来如引入用户可控 md 再行审视。

## 三、类型 / 编译隐患（静态核对）

> ⚠️ 因无法安装依赖，未能真实执行 `tsc` 编译；以下为逐文件静态核对。

### ✅ 3.1 未发现明显类型错误

- 前后端均开 `strict` + `noUnusedLocals` + `noUnusedParameters`，逐文件核对未发现未用局部变量
  或未用参数（`useBalances.clear`、`version.APP_NAME/APP_VERSION` 为导出项，不触发 noUnused）。
- 所有对象字段访问都做了 `as Record<string, unknown>` / 可选链 / `toNum` 宽容处理，避免运行时崩溃。
- `queryProvider` 的 switch 有 `default` 兜底（拒绝未知 id），`noFallthroughCasesInSwitch` 已满足。

### ⚠️ 3.2 【低】前端 CSS 副作用导入与 `noUncheckedSideEffectImports`

- `src/main.tsx` 有 `import "./index.css"`。该选项要求副作用导入有类型声明；
  `src/vite-env.d.ts` 引用了 `vite/client`（其声明了 `*.css` 模块），**静态判断可过**。
- 但因无法真实编译，此点未获实测确认，建议在有网环境跑一次 `npm run build` 最终坐实。

### ⚠️ 3.3 【低】`src/...` 与 `server/...` 各自 tsconfig 未纳入对方

- 前端 `tsconfig.json` 只 `include: ["src"]`、后端 `server/tsconfig.json` 只 `include: ["src"]`，
  两者不会互相影响，属于正常隔离，无循环依赖。
- 依赖拓扑为 DAG：`registry → types`、`query → types`、`hooks → registry/query`、`components → …`，
  **无循环依赖**。

### ⚠️ 3.4 【低】README 已过时（非编译问题）

- `README.md` 仍描述「聊天前端 / Token 配额统一管理与聊天工具」，目录结构也只列到 P1，
  与当前查询面板实现不符。建议在 **P7 README 收尾**时一并重写（任务也将其列入 P7）。

## 四、交互正确性

### ✅ 4.1 开关鉴权联动：实现正确

- `App.enableProvider`：先 `await refresh(id, creds)`，**成功（data 非空）才 `setEnabled(true)`**；
  失败返回 null → 不置 enabled（App.tsx 第 15–23 行）。
- `ProviderModule.handleSwitch`：ON 时先 `setEditing(true)` 展开编辑器，密钥未填则停在编辑态提示
  「请填写密钥后点击认证」；已填则 `pending` → 调 `onEnable()`（内部鉴权）。鉴权失败时父级未翻转
  enabled，开关视觉保持关闭、模块停留编辑态并显示红色中文错误 —— 即「失败回弹」。
- 关闭：`onDisable()` 置 enabled=false + 收起，符合「关闭即收起」。

### ✅ 4.2 加密输入隐藏：实现正确

- `SecretInput`：`type` 在 `password`/`text` 间切换，眼睛按钮带 `onMouseDown.preventDefault` 保焦点、
  `autoComplete/autoCorrect/autoCapitalize/spellCheck` 关闭；另有复制按钮 + 1.2s 成功态。

### ⚠️ 4.3 【高】5 家 Coding Plan 供应商的鉴权说明 md 缺失（P6 功能缺口）

- 注册表 9 家均设置 `docPath`，但 `public/docs/` 下**只有 4 个 md**：
  `qinyapi.md / deepseek.md / opencode-go.md / siliconflow.md`。
- **缺失**：`anthropic.md / zai.md / minimax.md / kimi.md / openrouter.md`。
- 结果：这 5 家的「? 浮窗」点击后 `fetch` 404 → 显示「加载说明失败…」（ProviderDocModal 第 61 行）。
- **建议**：在 P7 前补齐这 5 个 md（可参考现有 4 篇的「获取密钥 → 在 MyToken 填写 → 说明」结构），
  否则 P6 的「每供应商一份 md」目标未闭环。

### ⚠️ 4.4 【低】浮窗错误态不可重试

- `ProviderDocModal` 的 effect 有 `!isOpen || content !== null || error` 守卫；一旦某次 fetch 失败
  `error` 永久为 true（该模块实例生命周期内），**重开浮窗不会重试**。
- **建议**：为 `error` 增加「重试」或打开时重置 error，提升容错。

- 暗色基 `#0A0A0A/#111111/#1A1A1A`、亮色近白 `#FCFCFD`、蓝 `blue-500/600` + 紫 `indigo-500` 渐变、

### ⚠️ 5.2 【低】语义色 token 未落地 + 半透白度不统一

- `index.css` 的 `@theme` 定义了 `--color-canvas/surface/panel/card-dark`，但组件大量使用字面值
  （`dark:bg-[#0A0A0A]`、`bg-[#1A1A1A]`、`bg-[#111]`），语义 token 只在 root `bg-canvas` 用了一处；
- 半透白度取值不一：`ProviderCard bg-white/80`、模块 body `bg-white/60`、`BaseModal bg-white/95`。
- **建议**：视觉差异可接受，但为便于主题统一调整，可将浮层半透白/暗色基收敛为语义 token 或统一命名。

### ℹ️ 5.3 【提示】字体未自托管

- 因研发环境离线，`index.css` 采用系统字体栈回退（`@theme --font-*` 仅作参考），未实际嵌入三款 webfont。
- 属已知取舍，V1 可接受；如需精确呈现可在 `public/webfonts` 自托管后启用。
