## 关键决策（本轮）

1. **口径**：今日消耗 = 「今天第一次采样时刻 → 当前」的余额净减少（**不做累计**，按用户要求）。
   这是 DeepSeek 无官方统计接口 + 本项目不做 LLM 流量代理前提下的唯一可行路线。
2. **逐样本对累加而非仅首末差值**：两者在无充值/无异常时等价，但逐对可逐笔用
   `topped_up_balance` 增量把充值加回，避免出现负数或把充值当消耗。
3. **异常用「短间隔 + 大额」判据**（≤15 分钟且减少 ≥5 元）而非 `granted_balance` 差值：
   扣费是否优先扣赠送余额官方未明确，赠送减少与消耗在数值上不可区分。
   命中只提示 + 提供手动「重置基线」，不自动剔除（避免误删真实大额消耗）。
4. **采样写入放在 `useBalances.refresh` 成功分支**（查询唯一收敛点），而非组件 effect：
   自动刷新 / 手动刷新 / 启用认证三条路径天然一致，且无 StrictMode 双调用重复写入问题（同值去重兜底）。
5. **日界固定 Asia/Shanghai**（与官方账单、与 `PeakValleyView` 一致），不跟随浏览器时区。
6. **估算值不做累计、单位跟随余额币种**（顺带避开 `stats.today` 里硬编码 `USD` 的老问题——
   该处仍为 QinyAPI 专用，未改动，见「已知问题」）。

## 已知问题 / 待办

1. **`ResultView` 的 `stats.today` 单位硬编码 `USD`**（P4 遗留，当前只被 QinyAPI 使用，故未暴露）：
   若日后有非 USD 供应商复用 `stats.today`，需改为跟随币种。P8 走的是独立的「今日」行，未受影响。
2. **多端不一致**：采样只存本浏览器 localStorage；若需多端一致，需服务端存储**无密钥的样本**
   （新增持久化能力，超出 P8 范围，代理目前完全无状态）。
3. **浏览器后台节流**：跨零点那次采样不保证发生（标签页可能被节流/discard）；
   口径已按「最早采样」定义，不依赖零点必然采样。
4. **精度**：余额两位小数 → 日消耗接近 0.01 元时数字会跳或显示 0.00（UI 与文档均已说明）。
5. `deepseek-v4-pro` 价格行 TODO（2026-09-14 12:00 起下线并路由到 V4.1 Flash）——见 `registry.ts` 与
   `public/docs/deepseek.md` 的既有 TODO，与本轮无关但同期到期，需复核。
