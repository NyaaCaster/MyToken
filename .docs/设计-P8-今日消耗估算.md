# MyToken P8 设计笔记 —— DeepSeek「今日消耗（估算）」

> 本文记录 P8 的口径定义、算法、参数与边界；实现落在 `src/lib/dailySpend.ts` +
> `src/hooks/useDailySpend.ts`，类型与展示分别落在 `src/types/provider.ts`、
> `src/components/ProviderModule.tsx`。SSOT 见 `.docs/开发计划-SSOT.md` 的 P8 段。

## 一、背景与约束

- DeepSeek 开放平台**没有**可用 API Key 调用的用量/费用统计端点，官方仅提供
  `GET https://api.deepseek.com/user/balance`（`total_balance` / `granted_balance` /
  `topped_up_balance`，均为**字符串、两位小数**）。
- MyToken 不做 LLM 流量代理，因此无法像 dsh 费用统计插件那样用本地账本精确记账。
- 结论：**唯一可行路线是余额差值估算**（客户端采样余额，按差值推算消耗）。

## 二、口径（必须写进 UI，避免被当成官方账单）

> **今日消耗 = 从「今天第一次采样时刻」到「当前」的余额净减少，且剔除充值。**

推论（可接受的系统偏差）：

1. **系统性偏低**：首次采样时刻之前（00:00 → 首次采样）发生的消耗**无法观测**，永久丢失；
   页面全程关闭的时段同理。
2. 因此展示必须带「估算 · 自 HH:MM 起」，且不提供「累计」这类会被误读为账单的数字。
3. 采样越密越准：现有 5 分钟自动刷新 + 手动刷新 + 打开页面刷新即为采样点；
   页面若跨零点持续开着，00:00–00:05 之间的那次刷新即近似「00:00 基线」（不需要专门逻辑）。
   注意：后台标签页的 `setInterval` 会被浏览器节流甚至 discard，**不能假定零点采样必然发生**。

时间口径：日界固定 **Asia/Shanghai**（与官方账单、与模块内价格峰谷口径一致），
写法复用 `Intl.DateTimeFormat` + `timeZone: "Asia/Shanghai"`（同 `PeakValleyView`）。

## 三、算法

逐**相邻样本对**累加，而不是只取「首末差值」——两者在无充值/无异常时等价，但逐对累加
可以逐笔识别充值：

```
delta   = prev.total − cur.total                  // > 0 余额减少，< 0 余额增加（充值）
topUp   = max(0, cur.toppedUp − prev.toppedUp)     // 充值增量（仅当两侧都有 toppedUp）
part    = delta + topUp                            // 抠掉充值后的净消耗
spend  += max(0, part)                             // 负值（杂项增加）不计入，避免出现负数
```

- **充值**：充 100 元期间又消耗了 1 元 → `delta = −99`、`topUp = +100` → `part = 1` ✔
- 若上游未给 `toppedUp`（缺失），`topUp = 0` → 充值会被当成「余额上升」而**不产生负值**，
  只是该窗口内的消耗被吞掉（已知限制，见第六节）。
- **币种漂移**：只取与**最后一条样本同币种**的尾部连续子序列参与计算（多币种账户下
  `pickBalanceInfo` 可能前后选中不同币种，混算无意义）。
- `spend` 与采样窗口无关的「累计」不做——P8 明确不做累计。

## 四、参数（常量，集中在 `src/lib/dailySpend.ts`）

| 常量 | 值 | 理由 |
|---|---|---|
| `MAX_SAMPLES_PER_DAY` | 400 | 5 分钟自动刷新 ≈ 288 条/日，留余量；超限时保留**首条（基线）+ 最新若干条** |
| `KEEP_DAYS` | 7 | 只留最近 7 天，避免 localStorage 无限膨胀 |
| `SUSPECT_DELTA` | 5（元） | 单笔「余额变动 ≥ 5 元」且**相邻样本间隔 ≤ 15 分钟** → 标记疑似异常 |
| `SUSPECT_GAP_MIN` | 15（分钟） | 间隔超过 15 分钟的长间隔大额变动视为正常（页面关闭期间的正常消耗），不误报 |

## 五、异常检测（兜住赠送余额过期 / 平台调整）

- `granted_balance` 到期会**凭空减少余额**，与消耗在数值上不可区分（扣费是否优先扣赠送
  余额官方未明确，不能据此判定）。因此改用**「短间隔 + 大额」**判据：
  15 分钟内余额变动 ≥ 5 元 → 正常消费难以达到（pro 档 ¥27/百万输出 ≈ 18.5 万输出 tokens/15 分钟），
  更可能是赠送余额过期或平台调整。
- 命中时：今日块显示 ⚠ 提示 + **「重置基线」**按钮（清空当日样本并以当前余额重新起算，
  同时立即触发一次刷新写入新基线）。仅提示、不自动剔除，避免把真实大额消耗误删。
- 手动重置入口也是用户对「充值/过期/异常」的兜底手段。

## 六、已知限制（如实记录）

1. 精度：`total_balance` 为两位小数字符串 → 差值是**分**量级；日消耗接近 0.01 元时数字会跳、
   可能显示 0.00。日消耗 ≥ 0.1 元时完全够看。
2. 覆盖范围：只覆盖「采样点之间」的净消耗；00:00→首次采样、页面关闭期间不可观测 → 偏低。
3. 多端不一致：localStorage 按 origin + 浏览器隔离 → 手机/另一台电脑/不同域名入口各存一份，
   数字可能不同；清缓存即丢。（若日后要多端一致，需要服务端存储**无密钥的样本**，
   属于新增持久化能力，不属 P8 范围。）
4. 充值 + 消耗发生在同一采样间隔内时，只能得到净额（`toppedUp` 缺失时该间隔消耗被吞）。
5. 首次启用（认证成功）即写入第一条样本，此时「今日」显示 0.00 并标注起始时刻，属预期。

## 七、UI

DeepSeek 模块的额度数据区，**「余额」在左、「今日」在右，同一行并排**（`ProviderModule.tsx` 的
`ResultView`：`flex items-start justify-between`；右侧块 `text-right`，说明另起一行右对齐）：

```
余额  11.23 CNY                        今日  0.37 CNY  ⓘ
                                       估算 · 自 08:12 起   [重置基线]（仅异常时出现）
```

- 左块保持原「余额」形态（标签 + 金额 + 币种）。
- 右块为 P8 新增：标签 `今日` + 金额（两位小数），单位跟随余额币种（不是硬编码 USD）。
- 金额下方小字 `估算 · 自 HH:MM 起`，ⓘ 用 `title` 给出完整口径（浏览器原生 tooltip，不新增浮窗）；
  窄屏时该块内容在自身宽度内折行，不挤占余额行。
- 异常时在同一行追加琥珀色 `⚠ 异常变动` 与「重置基线」按钮。
- 无当日样本（如刚重置基线）显示 `— 等待采样`。

## 八、验证方式

1. `npm run build`（`tsc -b` + `vite build`）通过 —— 类型/编译证据。
2. 纯函数仿真（`computeFromSamples` 不依赖浏览器）：正常消耗 / 充值 / 充值+消耗同间隔 /
   赠送余额过期异常 / 跨天 / 币种漂移 / 同值去重 / 超限裁剪，逐条比对期望值。
3. `dist` 产物检查：新 UI 文案与存储键存在，保证构建确实带上了 P8。
4. 部署后 macmini 页面 200 + 产物校验。
